# 安全与合规清单

本 skill 涉及生产级工单系统，操作前务必遵守以下安全准则。

## 1. 凭据安全

- ✅ Token / PAT / 密钥一律从环境变量或密钥管理器读取（`${JIRA_API_TOKEN}` 引用）
- ✅ `.env` 加入 `.gitignore`，绝不提交 git
- ✅ 最小权限：只授予任务所需的 scopes（只读任务不配写权限）
- ✅ 定期轮换、离职吊销
- ❌ 绝不硬编码凭据到代码/配置/聊天输出
- ❌ 绝不在日志、报错、截图、粘贴内容中暴露完整 Token

## 2. 数据合规（重点）

- ⚠️ **内网 Jira 数据不得发往云托管服务**：内网/私有化 Jira 只能用本地 mcp-atlassian 直连，不能走官方远程 MCP（数据会经 Atlassian 云）
- ⚠️ 涉及敏感 issue（安全漏洞、人事、客户数据）时，先确认合规要求与可见范围
- ✅ 输出 issue 内容前注意脱敏：隐藏邮箱、手机号、内部密钥等

## 3. 操作安全

- ✅ 所有**写操作前向用户确认**：创建、更新、流转、删除、批量操作
- ✅ 先只读探测（`maxResults=1`）验证权限边界，再做真实操作
- ✅ 批量/全量操作（如批量流转、批量删除）必须逐条确认或先 dry-run
- ✅ 删除/归档类不可逆操作，格外谨慎，先备份相关信息
- ❌ 不绕过权限边界；用户无权限的操作不得尝试用其他账号/方式规避

## 4. 审计与可追溯

- ✅ 记录关键操作（谁、何时、对哪个 issue、做了什么）
- ✅ 操作后回读验证结果并汇报给用户
- ✅ 出错时不掩盖，报告真实错误便于排查

## 5. 限流与稳定性

- ✅ 429 限流指数退避，尊重 `Retry-After`
- ✅ 大结果分页，避免拉爆 API
- ✅ 失败重试仅用于幂等操作

## 6. 交付检查（操作完成前自检）

- [ ] 凭据未出现在任何文件/输出中
- [ ] 写操作均已获得用户确认
- [ ] 内网数据未经过云服务
- [ ] 操作结果已回读验证
- [ ] 未泄露敏感 issue 内容
