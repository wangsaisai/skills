# mea-cross-session skill

**mea-coding 的复制改造版**：把单会话的"管理-执行-审计"（MEA）编码工作流升级为跨会话消息版——管理者/执行者/审计者住在独立 Claude Code 会话（v2.1.224+ 跨会话消息），会话之间只传"子任务契约 + 执行报告 + 审计报告"，只有独立验证过的事实记入 `TASK_STATE.md`。可执行内容见 `SKILL.md`（运行时唯一加载的文件）。

## 与 mea-coding 的关系

| 维度 | mea-coding（单会话版） | mea-cross-session（本 skill） |
|---|---|---|
| 载体 | 一个会话里分饰三角 | 三个角色住独立会话，跨会话消息交接 |
| 上下文 | 同一会话内切换视角，上下文仍会增长 | 每轮执行者/审计者都是全新上下文 |
| 持久记忆 | 会话内表格；长任务落盘 TASK_STATE.md | `TASK_STATE.md` 是唯一持久记忆（必落盘） |
| 防腐化手段 | 每轮压缩账本 | 消息协议硬性规定"只传契约/报告/证据引用，不传轨迹" |
| 信任模型 | 执行者自述不算证据（纪律约束） | 执行者自述以 EXEC_REPORT 消息存在，仅 AUDIT_REPORT 能改账本（协议约束） |

共同点：验收契约先行、一轮一张契约、只读验证、只记验证过的事实、中途新需求不进当前轮。

## DeepSeek Harness 落地对照（2026-08-15 实测通过）

本 skill 最初按 Claude Code v2.1.224+ 跨会话消息设计，但**在 DeepSeek Harness（DSH）里可直接落地，无需任何改造**——DSH 原生具备全部对应机制，已用一轮真实演示验证（papers/check_index.py 三班倒：契约→执行→审计→记账）。

| mea-cross-session 概念 | DSH 里的实现 |
|---|---|
| 管理者（长期存活、持账本） | **主会话**（用户与主 agent 的对话） |
| 执行者 = 全新上下文会话 | 后台 `subagent`（默认不继承父上下文，持久 id，完成通知收 EXEC_REPORT，之后可用 `send_message` 唤醒续聊） |
| 审计者 = 独立只读会话 | 另一个后台 `subagent`（同样的全新上下文 + 只读约束写进 prompt） |
| 跨会话消息通道 | subagent 启动 prompt（发 CONTRACT）→ 完成通知（收 EXEC_REPORT / AUDIT_REPORT）→ `send_message`（追问、续派） |
| 唯一持久记忆 | `TASK_STATE.md` 落盘于共享工作区（另有 `goal` 工具可做跨轮长目标） |

**DSH 落地的三条硬规则**（实测踩过的坑）：

1. **用普通 `subagent`，禁用 `subagent_fork`**：fork 会继承父会话全部上下文，等于把"原始轨迹"传给了执行者/审计者——直接违反 SKILL.md 铁律第 2 条（消息永不携带原始轨迹）。执行者/审计者需要的一切（契约、验收标准、边界、证据引用）都写进启动 prompt，不靠上下文继承。
2. **执行者与审计者必须串行**：审计者要验收执行者的产出，必须先等执行者的完成通知；但多个互不冲突的契约可并行派多个执行者（注意失败模式第 14 条：并行执行者抢同一环境）。
3. **prompt 里给审计者写死"只读"约束**：subagent 共享主会话的文件权限，若不显式声明"不得创建/编辑/删除文件、只允许 cat/ls/find/运行脚本等只读命令"，审计者可能顺手改文件——那就等于没人审计。

**与 mea-coding 的分工（在 DSH 里）**：任务长、子任务边界清晰、想隔离验证或并行 → **mea-cross-session**（子代理三班倒）；短小、单轮、或想全程亲盯逐步验收 → **mea-coding**（主会话内分饰三角）。两者可混用：外层 mea-cross-session 分派子代理，子代理内部按 mea-coding 纪律干活。

## 提示词控制：用哪个 skill 由你怎么说决定

**控制原理**：DSH 的 skill 按名字或 description 触发——提示词里**点名 skill 名**最可靠（描述匹配可能因两个 skill 文案重叠而误触发）。三档写法：

**① 点名 mea-cross-session（派子代理三班倒）**

```
用 mea-cross-session 跑这个任务：<任务>。执行者和审计者都派独立子代理，
先写验收契约，干完只记验证过的事实到 TASK_STATE.md。
```

**② 点名 mea-coding（主会话内分饰三角）**

```
用 mea-coding 做：<任务>。先给我看验收契约和账本，每轮等我确认再继续。
```

**③ 不点名，让 agent 按任务特征自选（推荐用于你自己也拿不准时）**

```
<任务>。按任务情况自己选：子任务边界清晰、适合隔离验证就用 mea-cross-session
（派子代理），短小或需要我全程盯就用 mea-coding。
```

要点：**点名是硬控制**（"用 X skill"即可强制）；**描述触发条件是软控制**（说"派子代理三班倒"→ cross-session，"同一会话里分饰三角/每轮给我确认"→ mea-coding）。两个都提到 = 让 agent 按规模自选。
