# HarmonyOS AppGallery 上架 Skill

## 适用场景

This skill is relevant when:
- Configuring release signing (`.p12 / .cer / .p7b`) for a HarmonyOS app
- Editing `build-profile.json5` SDK version fields
- Setting `versionCode` / `versionName` before release
- Diagnosing cloud test device incompatibility in AppGallery Connect
- Troubleshooting signing or packaging errors during build

Read `references/publish_guide.md` for the detailed step-by-step reference.

## Key Concepts (Quick Reference)

### SDK Version Fields in `build-profile.json5`

| Field | Meaning |
|---|---|
| `compatibleSdkVersion` | Minimum installable OS version (install gate) |
| `targetSdkVersion` | Primary target/adaptation version |

**Rule**: `compatibleSdkVersion` controls which real devices can install the app. Raising it narrows your user base. Recommended baseline: `compatibleSdkVersion = "5.0.0(12)"`, `targetSdkVersion = "5.0.5(17)"`.

### Version Numbers in `AppScope/app.json5`

| Field | Type | Rule |
|---|---|---|
| `versionCode` | Integer | Must increment on every release. Never reuse. |
| `versionName` | String | Human-readable label shown in store (e.g., "1.0.0") |

### Release Signing — Three Required Files

1. **`.p12`** — Private key store, generated locally in DevEco Studio keystore tool
2. **`.cer`** — Certificate, applied for and downloaded from AppGallery Connect (AGC)
3. **`.p7b`** — Provisioning profile, generated in AGC and bound to `.cer` + app bundle

All three must be consistent (same key alias, same app bundle ID).

### `build-profile.json5` Release Signing Config (Minimal)

```json5
"signingConfigs": [
  {
    "name": "release",
    "type": "HarmonyOS",
    "material": {
      "storeFile": "path/to/your.p12",
      "storePassword": "...",
      "keyAlias": "your_key_alias",
      "keyPassword": "...",
      "signAlg": "SHA256withECDSA",
      "profile": "path/to/your.p7b",
      "certpath": "path/to/your.cer"
    }
  }
]
```

### Debug vs Release Package

- **Debug**: signed with debug certificate (auto-generated by DevEco), cannot be published
- **Release**: signed with release certificate from AGC, required for upload and cloud test

Build → Generate Signed Bundle in DevEco Studio, select "Release" profile.

### Cloud Test Device Compatibility

Cloud test device availability ≠ real user install compatibility.

- Cloud test "device not compatible" usually means the device pool has no idle machines matching that API level at that moment, NOT that the app has a compatibility bug.
- Real users: any device with OS API level ≥ `compatibleSdkVersion` can install the app.
- Raising `compatibleSdkVersion` to match cloud test machines will narrow the real install base. Avoid this unless intentional.

### Layered App Icon (分层图标)

Huawei cloud test **requires** layered icon (foreground + background), each 1024×1024px, no rounded corners, no padding.

**Directory structure** (both AppScope and entry module):
```
AppScope/resources/base/media/
├── foreground.png       # Foreground: icon graphic on transparent background
├── background.png       # Background: solid/gradient color
└── layered_image.json   # Layer mapping config
```

**`layered_image.json`** (must be in `media/`, NOT `profile/`):
```json
{
  "layered-image": {
    "background": "$media:background",
    "foreground": "$media:foreground"
  }
}
```

**Config references** (in `app.json5` and `module.json5` abilities):
```json5
"icon": "$media:layered_image"
```

**Pitfalls encountered**:
1. File names must be `foreground.png` / `background.png` — do NOT use `app_icon_foreground.png` prefix
2. `layered_image.json` must go in `media/` directory, NOT `profile/`
3. `icon` field only accepts `$media:xxx` pattern — `$profile:xxx` will cause schema validation error
4. `$media:layered_image` references the JSON file by name (without extension), which then maps foreground/background
5. Both AppScope and entry module should have identical copies of the 3 files (foreground.png, background.png, layered_image.json)
6. The old `app_icon.svg` can coexist without conflict

## Common Errors

| Error | Cause | Fix |
|---|---|---|
| `SignHap: key alias not found` | `keyAlias` in config doesn't match alias in `.p12` | Check alias name exactly in DevEco keystore tool |
| `File content is not certificates` | `.cer` path points to wrong file (e.g., `.p7b` or `.p12`) | Verify each file's extension and content |
| `versionCode must be greater than previous` | Forgot to increment `versionCode` | Increase integer value in `app.json5` |
| Cloud test: all devices "not compatible" | API level mismatch with device pool | Temporarily raise `targetSdkVersion`; do NOT raise `compatibleSdkVersion` |
| Build produces `.hap` but AGC rejects it | Uploaded debug `.hap` instead of release | Rebuild with release signing config |
| Cloud test: "应用未配置图标的前景图和后景图" | Missing layered icon resources or wrong config | Follow layered icon setup above; ensure file names, directory, and `$media:layered_image` reference are correct |
| Build schema error on `app.icon` pattern | Used `$profile:xxx` instead of `$media:xxx` | `icon` field only accepts `$media:xxx`; change to `$media:layered_image` |
| Cloud test warning: 页面可滑动控件上滑到顶部或下滑到底部时缺少回弹动效 | `Scroll` component missing `edgeEffect`; default is `EdgeEffect.None` | Add `.edgeEffect(EdgeEffect.Spring)` to every `Scroll()` attribute chain in all scrollable pages |
| ArkTS 10505001: `Property 'edgeEffect' does not exist on type 'StackAttribute'` | Page uses `Stack(Scroll + overlay)` structure; `.edgeEffect()` was added to the outer `Stack` attribute chain instead of `Scroll` | Move `.edgeEffect(EdgeEffect.Spring)` to the `Scroll` attribute chain (after `.align(Alignment.TopStart)`), remove it from `Stack` |
